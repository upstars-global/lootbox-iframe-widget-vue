Загальний опис

Цей документ містить всю необхідну інформацію для інтеграції віджета лутбокса через iframe. Лутбокс комунікує з батьківським сайтом через PostMessage API, а тексти та стан встановлюються через query параметри.

**Підтримка мультипроектності:** Віджет підтримує роботу з різними проектами (Alpa, King, Thor тощо). Кожен проект має свою дефолтну тему.

Приклади посилань на iframe:

Для проекту Alpa:
https://rocketplay-bonuses.club/lootbox/index.html?project=alpa

Для проекту King:
https://cdn-wl.s3.amazonaws.com/common/lootbox/king/index.html?project=king

Адреса iframe має починатися з `https://`: на сайтах під https браузер блокує iframe з `http://`.

Наглядний тест взаємодії з батьківським сайтом:
https://rocketplay-bonuses.club/lootbox/test-lootbox.html

Як приймати повідомлення від лутбокса

Віджет надсилає повідомлення батьківській сторінці з `targetOrigin = '*'`, тому перевіряти відправника має сайт. Обробник на сайті повинен прийняти повідомлення лише якщо:

- `event.source === iframe.contentWindow` — повідомлення прийшло саме з вашого iframe, а не з іншого вікна чи фрейма на сторінці;
- `event.origin` дорівнює origin колеса (схема, хост і порт з адреси iframe, без шляху), наприклад `https://rocketplay-bonuses.club`.

```javascript
const WHEEL_ORIGIN = 'https://rocketplay-bonuses.club'
const iframe = document.getElementById('lootbox-iframe')

window.addEventListener('message', event => {
  if (event.source !== iframe.contentWindow) return
  if (event.origin !== WHEEL_ORIGIN) return
  if (!event.data || typeof event.data !== 'object') return

  if (event.data.type === 'lootboxReady') {
    // розблокувати кнопку "Спін"
  }
  if (event.data.type === 'spinEnd') {
    // показати попап; приз для виплати брати з відповіді бекенда
  }
})
```

Приз для нарахування береться з відповіді бекенда. Поле `prize` у `spinEnd` призначене лише для показу користувачу: його надсилає сторінка в iframe, а не сервер.

Повідомлення від лутбокса (вихідні фронту)

1. 'lootboxReady'

Коли надсилається: після того, як завантажились CSS теми та зображення колеса (очікування зображень обмежене в часі, тому одне зламане зображення не блокує старт). Якщо `themes/themes-config.js` або `theme.css` не завантажились, повідомлення не надсилається, а на екрані лишається прелоадер.

Формат:
javascript
{
type: 'lootboxReady'
}

Що потрібно зробити:

- (Опціонально) зберегти стан готовності віджета
- Розблокувати UI (кнопку "Спін")
- Можна починати відправляти команди до лутбокса

---

2.  'spinEnd'

Коли надсилається: приблизно через 6 секунд після зупинки колеса, коли ще відображається анімація виграшу (вона триває 9 секунд). Зупинка колеса і відправка не залежать від відмальовування кадрів, тому відбуваються вчасно і у фоновій вкладці.

Формат:
javascript
{
type: 'spinEnd',
data: {
prize: '500 USD', // Текст призу з виграшного сектора: значення і валюта через пробіл (лише для показу)
timestamp: 1730000000000 // Час відправки, мс (Date.now())
}
}

Якщо для виграшного сектора немає даних (призів менше, ніж секторів, або список призів порожній), `prize` — порожній рядок. Віджет не надсилає сайту повідомлення `winSector`: цей тип лише вхідний.

Що потрібно зробити:

- Обробити результат; виплату і нарахування робити за відповіддю бекенда, а не за `prize`
- Показати попап користувачу про виграш
- Можливо залогувати результат (аналітика, бекенд)
- Можливо скинути стан для наступної гри

Повідомлення до лутбокса (з фронта)

1.  'startSpin'

Коли відправляти: Коли користувач ініціює обертання (натискає кнопку Spin).

Формат:
javascript
{
type: 'startSpin'
}

Що відбувається:

- Колесо починає обертатися зі сталою швидкістю
- Без результату колесо крутиться циклами по 3 секунди, поки не прийде 'winSector' (команди «зупинитися» немає)
- Якщо колесо вже крутиться, 'startSpin' ігнорується
- Новий спін скасовує очікувані події попереднього: якщо запустити його до отримання 'spinEnd', попереднє 'spinEnd' не прийде

Важливо:

- Відправляйте тільки після отримання 'lootboxReady'
- Після відправки відразу робіть запит на бекенд для отримання виграшного сектора

---

2.  'winSector'

Коли відправляти: Після отримання виграшного сектора з бекенда.

Формат:
javascript
{
type: 'winSector',
data: 5 // Індекс виграшного сектора: число від 0 до 7 (Number)
}

Правила:

- `data` — Number, індекс сектора в списку 'sectors': 0 — перший приз, 7 — восьмий
- Числовий рядок (наприклад, '5') приводиться до числа і приймається
- Некоректне значення (null, '', true, 8, -1, 5.5, 'abc') ігнорується з `console.error` у консолі iframe; колесо продовжує крутитися і чекає на коректний номер
- Верхня межа — кількість призів мінус 1 (7, якщо список призів порожній)
- Якщо 'winSector' прийшов під час обертання, колесо зберігає швидкість і сповільнюється 14 секунд від цього моменту; якщо номер відомий ще на старті — 14 секунд від старту
- 'winSector', надісланий до 'startSpin' або після зупинки колеса, зберігається і використовується наступним спіном
- Після зупинки колесо тримає результат: анімація виграшу 9 секунд, ще 30 секунд колесо стоїть на виграшному секторі, потім за 2 секунди плавно повертається в очікування

Query-параметри для URL iframe

'project'

- Тип: String
- Опис: Назва проекту для визначення дефолтної теми
- Доступні значення:
  - 'alpa' - проект Alpa (дефолтна тема: AlpaWheelLight)
  - 'king' - проект King (дефолтна тема: KingWheel)
  - 'thor' - проект Thor (дефолтна тема: ThorWheel)
- Приклад: '?project=king'
- ⚠️ Важливо: Якщо вказано `project`, але тема (`style`) не належить цьому проекту — буде використано дефолтну тему проекту (з `console.warn` у консолі iframe)
- ⚠️ Важливо: Невідомий `project` — `console.error` і запасна тема AlpaWheelLight

'ab'

- Тип: Boolean
- За замовчуванням: не встановлено (A/B вимкнено)
- Опис: Активує A/B тестування для проекту
- Приклад: '?project=alpa&ab=true'
- ⚠️ Важливо: A/B тестування працює ТІЛЬКИ якщо:
  - Передано `?ab=true`
  - Вказано `?project=`
  - НЕ вказано `?style=` (інакше буде використано вказану тему)
  - Для проекту налаштовано A/B тест в конфігурації
- Варіант визначається за `user_id` з URL (див. 'user_id'): без нього віджет бере випадковий id з localStorage, а при заблокованому сховищі кожне завантаження отримує новий id і, відповідно, може показати інший варіант

'style'

- Тип: String
- Опис: Назва теми візуального оформлення (саме назва, не числовий id)
- Доступні на даний момент значення:
  - 'AlpaWheelLight' - тема для Alpa Wheel Light (дефолт для проекту Alpa)
  - 'AlpaWheelPro' - тема для Alpa Wheel Pro
  - 'AlpaWheelMax' - тема для Alpa Wheel MAX
  - 'AlpaWheelMart' - тема для Alpa Wheel Mart
  - 'KingWheel' - тема для King (дефолт для проекту King)
  - 'ThorWheel' - тема для Thor (дефолт для проекту Thor)
- Приклад: '?style=AlpaWheelPro' або '?project=alpa&style=AlpaWheelPro'
- ⚠️ Важливо: Явне вказання `?style=` вимикає A/B тестування — користувач отримає саме вказану тему
- ⚠️ Важливо: `?style=` без `?project=` приймається як є (зворотна сумісність); тема з `?style=` разом з `?project=` використовується лише якщо належить цьому проекту

**Legacy-назви (Rocket → Alpa)**

Проект `rocket` перейменовано на `alpa`, теми `RocketWheel*` — на `AlpaWheel*`. Старі
посилання продовжують працювати: значення нормалізуються автоматично на старті віджета.

| Старе значення           | Нове значення    |
| ------------------------ | ---------------- |
| `?project=rocket`        | `?project=alpa`  |
| `?style=RocketWheelLite` | `AlpaWheelLight` |
| `?style=RocketWheelPro`  | `AlpaWheelPro`   |
| `?style=RocketWheelMAX`  | `AlpaWheelMax`   |

Нові інтеграції варто робити одразу на нових назвах.

'user_id'

- Тип: String
- За замовчуванням: не встановлено
- Опис: ID користувача для A/B розподілу і для аналітики
- Приклад: '?user_id=12345'
- Використання: Передається в GA4 для User-ID reporting, додається до кожної аналітичної події як `user_id` і входить у розрахунок A/B варіанту
- ⚠️ Важливо: Для стабільного A/B варіанту передавайте `user_id`. Без нього віджет бере випадковий id з localStorage браузера (а якщо сховище заблоковане — новий id при кожному завантаженні)

Логіка вибору теми:

1. Якщо передано `?style=` без `?project=` — використовується вказана тема (зворотна сумісність), A/B тест вимкнено
2. Якщо передано `?project=` + `?style=` — валідується належність теми до проекту, A/B тест вимкнено
3. Якщо передано `?project=` + `?ab=true` (без `?style=`):
   - Якщо для проекту налаштовано A/B тест — тема обирається на основі варіанту користувача
   - Якщо A/B тест не налаштовано — використовується дефолтна тема проекту
4. Якщо передано тільки `?project=` (без `?style=` та без `?ab=true`) — використовується дефолтна тема проекту, A/B вимкнено

'sectors'

- Тип: String (розділені крапкою з комою)
- Опис: Список призів для секторів колеса
- Формат: Текстові значення через крапку з комою (;): '"500 USD; 5,000 USD; 10 FS; ..."'
- Формат одного призу: «значення пробіл валюта», наприклад '500 USD' або '10 FS'. Значення — до першого пробілу, решта — валюта. Приз без пробілу ('JACKPOT', '150%') показується цілим як значення, з порожньою валютою
- Кількість: Рівно 8 призів — колесо має 8 секторів. Якщо призів менше, частина секторів лишається порожньою, а номер сектора, якого немає в списку, 'winSector' відхилить; список з менш ніж 2 чи більш ніж 8 призів вважається некоректним, і всі сектори порожні
- Кількість має збігатися з кількістю 'sectors_type'
- URL encoding: Пробіли та спецсимволи повинні бути закодовані ('%20' для пробілів, '%3B' для крапки з комою)
- Декодований приклад: '500 USD; 5,000 USD; 10 FS; 20 FS; 35 FS; 25 USD; 100 USD; 250 USD'
- ⚠️ Важливо: Використовуйте крапку з комою (;) як розділювач, щоб підтримувати коми в сумах (наприклад, "5,000 USD")

'sectors_type'

- Тип: String (розділені крапкою з комою)
- Обов'язковий: так. Без 'sectors_type' список призів порожній: колесо без текстів, а 'winSector' приймає лише номери 0..7 без призу в 'spinEnd'
- Опис: Типи призів для кожного сектора
- Формат: Текстові значення через крапку з комою (;)
- Кількість: Має відповідати кількості 'sectors'
- Типові значення:
  - 'Bonus Prize' - бонусні призи
  - 'Free Spins' - безкоштовні спіни
  - 'Cash Prize' - готівкові призи
  - Або будь-які кастомні назви
- Декодований приклад: 'Bonus Prize; Bonus Prize; Free Spins; Free Spins; Free Spins; Bonus Prize; Bonus Prize; Bonus Prize'

'active'

- Тип: Boolean
- За замовчуванням: 'true'
- Опис: Визначає чи активний лутбокс
- Використання: Встановіть 'false' якщо користувач зараз не може прокрутити колесо: віджет показується приглушеним і без анімацій
- Також передається в кожну аналітичну подію як `active` ('true' або 'false'), щоб перегляди з використаним спіном можна було відфільтрувати
- Приклад: '?active=false'

'vip_level'

- Тип: Number (integer >= 0)
- За замовчуванням: '0'
- Опис: VIP рівень гравця
- Приклад: '?vip_level=5'
- ⚠️ Важливо: Віджет цей параметр не читає: він не впливає ні на колесо, ні на аналітику. Параметр можна передавати, але ефекту не буде.

'season'

- Тип: String
- За замовчуванням: не передається — сезон обирається автоматично за датою (UTC)
- Опис: VIP-сезон для теми 'AlpaWheelMax' — міняє колір кристала в поінтері та в центрі колеса
- Значення: 'milky-way', 'orion-nebula', 'eagle-nebula', 'andromeda' або 'none' (базовий вигляд)
- Приклад: '?season=orion-nebula'
- ⚠️ Важливо: Передавати не обов'язково. Параметр потрібен, лише якщо сайт хоче сам задати сезон гравця; на інші теми не впливає. Для перевірки меж сезонів є QA-параметр 'season_at' (час у UTC, напр. '?season_at=2027-01-04T10:01:00Z').

FullStory та 'no_analytics'

- Параметра `fs_org` немає — його значення ігнорується
- FullStory вмикається автоматично за параметром `?project=`: для проектів alpa та king скрипт FullStory вантажиться з вшитим в `index.html` Org ID. Для thor та для запитів без `?project=` FullStory не завантажується
- Скрипт автоматично встановлює `_fs_run_in_iframe = true` для коректної роботи в iframe
- 'no_analytics' (Boolean, наявність параметра): `?no_analytics` вимикає і події (`track`), і завантаження FullStory. Потрібен для превʼю-фреймів та тестів
- Приклад: '?project=alpa&no_analytics'

Приклад повного URL:

```
?project=alpa&user_id=12345&sectors=500%20USD;1000%20USD;10%20FS;20%20FS;35%20FS;25%20USD;100%20USD;250%20USD&sectors_type=Bonus%20Prize;Bonus%20Prize;Free%20Spins;Free%20Spins;Free%20Spins;Bonus%20Prize;Bonus%20Prize;Bonus%20Prize
```

'fps' (опціональний параметр)

- Тип: Boolean
- За замовчуванням: 'false'
- Опис: Показує FPS-монітор для діагностики продуктивності
- Використання: Для debug режиму
- Приклад: '?fps=true'

Аналітичні події

Віджет автоматично відправляє аналітичні події до FullStory (якщо він увімкнений для проекту) та Google Analytics 4. З `?no_analytics` не відправляється нічого.

| Подія           | Коли відправляється                                                                                   | Ключові параметри                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `Widget Loaded` | Коли колесо готове (разом з `lootboxReady`)                                                           | `theme`, `project`                                                                   |
| `Lootbox View`  | Разом з `Widget Loaded`                                                                               | `theme`, `project`                                                                   |
| `Spin Started`  | Коли колесо справді починає обертатися (`startSpin` під час обертання ігнорується і подію не створює) | `theme`, `project`                                                                   |
| `Spin Ended`    | Разом з відправкою `spinEnd`                                                                          | `prize`, `sector`, `theme`, `project`, `prize_type`, `prize_value`, `prize_currency` |

**Загальні параметри:** кожна подія отримує `session_id`, `host` (домен батьківської сторінки з referrer), `env` ('dev' або 'prod') і `active` ('true' або 'false'), а також `user_id`, якщо він переданий в URL.

**A/B параметри:** Якщо активний A/B тест, до кожної події автоматично додаються `ab_test_id` та `ab_variant`.

**Доступ до A/B інформації:**

```javascript
// В консолі браузера (всередині iframe)
window.currentTheme.abTest
// Результат: { testId: 'alpa_theme_v2', variantId: 'A' } або null
```
